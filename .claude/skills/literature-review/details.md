# Literature Review Workflow

먼저 `CLAUDE.md`와 `ref/literature-review.md`를 읽고 연구 질문, 실험 구성, 조사 범위를 파악합니다.
`ref/papers/`에 있는 논문은 직접 읽고 앵커로 사용합니다.

주제에 대한 짧은 slug를 생성합니다 (소문자, 하이픈 포함, 불필요한 단어 없음, 5단어 이하).
이 slug는 이번 실행에서 사용하는 모든 파일에 사용합니다.

## Workflow

1. **계획 수립** — 조사 범위를 개략적으로 정리합니다. 주요 질문, 검색할 자료 유형(논문, 웹), 기간,
   예상 섹션, 간단한 작업 목록 및 검증 로그를 포함합니다.
   계획과 검증 로그는 `ref/_review/<slug>_plan.md`에 저장합니다.

2. **자료 수집** — 조사 범위가 넓으면 `ref/literature-review.md`의 조사 주제별로 `researcher` 하위 에이전트를
   병렬로 실행합니다. 각 에이전트에게 출력 경로를 반드시 지정합니다: `ref/_review/<slug>_research_<주제>.md`.
   출처 기준은 researcher 정의(SCIE/SSCI Q1 우선, 사분위 확인)를 따릅니다.
   주제가 좁은 경우에는 직접 검색합니다.

3. **종합** — 합의점, 이견, 미해결 질문을 구분합니다. 필요한 경우 구체적인 다음 실험이나 후속 연구를 제안하고,
   CLAUDE.md의 실험 1~3과 어떻게 연결되는지 명시합니다.
   논문 간 정량적 비교가 필요하면 matplotlib으로 차트를 만들어 `figures/<slug>_*.png`에 저장하고,
   Mermaid 다이어그램으로 분류 체계 또는 방법론 파이프라인을 시각화합니다.
   초안을 완성하기 전에 모든 강력한 주장을 검증 로그와 대조하고, 추론된 내용이나 단일 출처 주장은 표현을 낮춥니다.
   초안은 `ref/_review/<slug>_draft.md`에 저장합니다.

4. **인용** — `verifier` 에이전트로 인라인 인용을 추가하고 모든 출처 URL을 검증합니다.
   출력 경로: `ref/_review/<slug>_cited.md`.

5. **검증** — `reviewer` 에이전트로 근거 없는 주장, 논리적 오류, 불필요한 섹션, 단일 출처 의존을 확인합니다.
   출력 경로: `ref/_review/<slug>_review.md`.
   제출 전에 오류를 수정하고, 주요 문제는 미해결 질문에 기록합니다.
   치명적인 오류가 발견되면 수정 후 검증을 한 번 더 실행합니다.

6. **제출** — 최종 문헌 검토를 `ref/<slug>.md`에 저장합니다.
   마지막 섹션은 "시뮬레이터·실험 설계에 대한 시사점"으로 구성합니다.

7. **설계 점검** — 최종 리뷰의 시사점을 `CLAUDE.md`의 모델 가정, 그래프 설계, 실험 구성과 대조해
   문헌이 뒷받침하는 설계, 문헌과 다른 설계, 근거가 없는 설계를 구분하고
   `ref/plan/<slug>_spec_audit.md`에 기록합니다. `CLAUDE.md`는 직접 수정하지 않고 제안만 남깁니다.
