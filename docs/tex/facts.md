## 1. 연구 개요 (CLAUDE.md 원문)

[사실] 근거: `CLAUDE.md:12-19` (연구 질문·방법), `CLAUDE.md:33-68` (실험 구성), `CLAUDE.md:70-74` (비교 기준). 아래는 원문 그대로다.

> 연구 질문: 현재의 매칭·잉여배분이 미래 참여자 구성을 바꾸는 플랫폼에서,
> 미래 가치를 어떻게 근사해야 동적 의사결정이 개선되는가?
>
> 방법: 시뮬레이션 경험으로 미래 가치 V(s)를 학습(선형 / MLP / GNN) →
> 참여자별 유지 가치 c_i = V(s) − V(s에서 참여자 i 제외) (주문자·공급자 모두) →
> MILP 목적함수 = 당기 이윤 + Σ c_i × 재참여확률_i(배분 잉여) (재참여확률은 구간선형 근사).
> 경험 수집과 시뮬레이션 기준치의 후속 정책은 규칙 기반 잉여배분 정책(최선 공급자 몫 비율)이다.
> 근시안(유지 가치 0)은 잉여를 전부 플랫폼이 가져가 참여자 대부분이 떠나므로, 미래를 전혀 고려하지 않을 때의 참고용 하한으로만 둔다.

> - 실험 1 (선형 근사의 한계와 학습된 근사의 필요성):
>   같은 시장 요약 지표를 줄 때, 선형 근사(기존 ADP)와 신경망 근사의 미래 가치 예측 정확도와
>   장기 성과는 어떻게 다른가?
>   → 검증할 가설: 지표들 사이에 조합 효과가 있다면 신경망의 예측 오차가 더 작고 장기 성과가 높다.
>   → 반대 결과의 의미: 차이가 없으면 이 환경의 미래 가치는 선형으로 충분히 설명된다.
>   → 측정: 시뮬레이션 기준치 대비 예측 오차, 유지 가치 변환 후 추가 오차, 누적 이윤·주문 충족률·참여자 유지율
>
> - 실험 2 (반응 함수에 대한 강건성):
>   재참여 반응이 로지스틱이 아닐 때 학습된 근사의 성능은 어떻게 변하는가?
>   → 두 경우: 바뀐 반응에 맞춰 재학습 / 로지스틱으로 학습하고 다른 반응 환경에서 평가
>   → 결과 해석: 재학습 시 유지되면 방법이 특정 반응 가정에 묶이지 않음을,
>     불일치 시 저하 폭은 반응 모형 추정이 얼마나 중요한지를 보여준다. 저하가 크든 작든 그대로 보고한다.
>
> - 실험 3 (구조 정보의 유효 조건):
>   시장 요약 지표만 쓰는 신경망(MLP)과, 거래 연결 구조를 그래프로 반영한 신경망(GNN)의
>   성과는 어떤 시장 구조 조건에서 달라지는가?
>   → 검증할 가설: 공급 편중도를 올릴수록, 대체 공급자가 적을수록, 주문당 품목 수가 많을수록
>     구조 정보의 효과가 커진다. 공급 편중도는 수준별 추세로 검증한다.
>   → 대조 조건 (차이가 없어야 함): 주문당 품목 수 1. 공급자 구조는 그대로 두고 주문만 단품으로 바꾼 시장이다.
>     묶음 주문이 없으면 공급자가 떠날 때의 손해가 품목별로 따로 더해지므로, 시장 요약 지표만으로 충분하고
>     거래 연결 구조가 주는 추가 정보가 없다. 이 조건에서 두 방법의 차이는 통계적으로 구분되지 않아야 하며,
>     차이가 나면 해석 전에 구현 차이(파라미터 수, 학습량)를 먼저 점검한다.
>   → 공급 편중도 0은 대조 조건이 아니라 기준 수준이다. 모든 공급자가 같은 수의 품목을 맡아도
>     어떤 품목끼리 같은 공급자에 묶이는지가 남아 있어서 차이가 날 수 있다.
>   → GNN이 "MLP + 편중도 요약" 비교군보다 나은지가 구조 정보 효과의 판단 기준이다.
>   → 반대 결과의 의미: 모든 조건에서 차이가 없으면, 유지 가치 변환에서 구조 정보가 소실되었거나
>     이 규모에서는 시장 요약 지표만으로 충분하다는 뜻이며, 둘 중 무엇인지 변환 오차로 구분한다.
>   → 핵심 설계: n_alt 2 고정, 공급 편중도 {0, 0.5, 1} × 주문당 품목 수 {1, 2, 3}.
>   → 보조 설계: n_alt 3. 공급자 수가 고정이므로 공급자당 평균 품목 수(2 → 3)가 함께 바뀌어
>     대체 공급자 수의 효과와 섞인다는 점을 결과에 명시한다.
>   → n_alt 1은 공급 편중도를 바꿀 수 없어(모든 공급자가 1품목) 실험 3에서 제외한다.
>     대조 조건으로도 쓰지 않는다: 대체 공급자가 없는 극단적인 시장이라, 차이가 없게 나와도
>     구조 정보가 없어서인지 시장이 극단적이어서인지 구분할 수 없다.
>   → 측정: 누적 이윤·주문 충족률·참여자 유지율, 유지 가치 변환 오차

> 비교 기준: 규칙 기반 잉여배분(사전에 정한 고정 비율로 배분. 공급자 몫은 기본값 0.3보다 튜닝용 반복에서 유의하게 나은 후보가 있을 때만 바꿈.
> 가치 근사 정책의 주 비교 기준),
> 근시안 정책(유지 가치 0, 미래를 전혀 고려하지 않을 때의 참고용 하한),
> 선형 가치 근사(기존 ADP: 시장 요약 지표의 선형 결합으로 미래 가치 근사),
> MLP + 편중도 요약(시장 요약 지표에 공급자별 품목 수의 최댓값·분산을 더한 MLP, 실험 3의 GNN 비교군)

[사실] 비교 기준 문장의 "공급자 몫은 기본값 0.3보다…"는 현재 코드와 다르다. 지금 규칙 기반은 **주문자 몫과 공급자 몫을 함께** 4×4 격자에서 고른다 (`src/bench/rule_split.py:17-20`, `Cfg.sh_buy_grid`·`sh_sup_grid` = `src/utils/params.py:66-67`). 기준 몫은 `sh_ref = (0.3, 0.3)`이다 (`params.py:63`).

### 2.5 시장 조건 세 가지와 생성 알고리즘

[사실] 정의 (`CLAUDE.md:26-29`):
- 공급 편중도 `conc`(0~1): 공급자–품목 연결을 공급자들이 얼마나 고르게 나눠 갖는지.
- 대체 공급자 수 `n_alt`: 한 품목을 공급할 수 있는 공급자 수.
- 주문당 품목 수 `items_per_order`(k): 주문 하나에 묶인 품목 수.

[사실] 공급자별 품목 수 계산 (`src/utils/instance.py:40-53`):
- 연결 수 L = `n_items × n_alt`, 공급자 수 S, 품목 수 I (41). 조건 `n_alt ≤ S ≤ L`을 검사한다 (42).
- 균등 수열 `eq`: 모든 공급자에 `L // S`를 주고, 앞쪽 `L mod S`명에 1을 더한다 (43-44).
- 최대 편중 수열 `mx`: 모두 1에서 시작한다. 남은 `r = L − S`개를 공급자 순서대로 `min(I − 1, r)`씩 몰아준다 (45-49).
- 섞기: `x = round((1 − conc)·eq + conc·mx, 9)`, `d = floor(x)` (50-51).
- 합 보정: `d`의 합이 L이 되도록 소수 부분이 큰 공급자부터 1씩 더한다 (안정 정렬, 52).

[사실] 연결 배정 (`src/utils/instance.py:57-66`, Ryser 탐욕법):
- 품목마다 "필요 공급자 수" `need = n_alt`에서 시작한다 (59).
- 품목 수가 많은 공급자부터(안정 정렬, 61) 자기 품목 수만큼 품목을 고른다. 1순위는 `need`가 큰 품목, 동률은 인스턴스 난수로 가른다 (62). 고르면 `need`를 1씩 줄인다 (63-64).
- 끝나면 모든 `need = 0`을 검사한다 (65).

[사실] 실제 생성 결과 (rep 0, `utils.instance.make`로 이 문서 작성 시 확인. 공급자 자리 순서):
- n_alt 1: conc 0, 0.5, 1 모두 [1,1,1,1,1,1].
- n_alt 2: conc 0 [2,2,2,2,2,2], conc 0.5 [4,2,2,2,1,1], conc 1 [6,2,1,1,1,1].
- n_alt 3: conc 0 [3,3,3,3,3,3], conc 0.5 [5,4,3,2,2,2], conc 1 [6,6,3,1,1,1].

[사실] 주문당 품목 수 k는 주문자 프로필의 품목 수이고, 수량 범위를 함께 조정한다(2.8절). 공급자 구조와 주문자 수는 k와 무관하다 (`tests/test_arrivals.py::test_items_per_order_keeps_supply`).

### 2.6 가격 수준 생성 (price_rank)

[사실] `Cfg.price_rank: bool = True`가 기본값이다 (`params.py:35-37`).

[사실] `price_rank=True` (새 방식, 실험 3부터; `instance.py:83-87, 96`):
- 인스턴스마다 `U[i, k] ~ Uniform(0.8, 1.1)`을 품목 × 순번(n_items × n_alt) 행렬로 뽑는다 (84).
- 품목 i의 공급자들에게 **공급자 자리 순서대로** `U[i, 0..n_alt−1]`을 준다 (85-86). 공급자 j의 품목 i 가격은 `base_i × U[i, rank]`다 (87).
- 빈자리 충원 공급자는 품목마다 새 수준 `Uniform(0.8, 1.1)`을 뽑는다 (96, 크기 n_items).

[사실] `price_rank=False` (기존 방식, 실험 1까지; `instance.py:89, 94-97`): 공급자마다 가격 수준 하나 `~ Uniform(0.8, 1.1)`을 뽑아 그 공급자의 모든 품목에 쓴다 (96, 크기 None). 충원 공급자도 같다.

### 2.7 공급용량 계산

[사실] 계산식 (`src/utils/instance.py:75-81`):
- 안정 상태 활동 주문자 수 `act = lam_buy / (1 − ret_ss) = 10.0 / (1 − 0.5) = 20.0` (75, `ret_ss = 0.5` = `params.py:40`).
- 품목별 안정 상태 수요 `dem = act × k / n_items × (lo + hi) / 2`. 기본(k = 2, 범위 6–15)에서 `20.0 × 2/6 × 10.5 = 70.0`이다 (77). k = 1(12–30)과 k = 3(4–10)도 `70.0`이다(이 문서 작성 시 계산).
- 품목별 총 공급용량 `tot = round(cover × dem / occ)` (78). `cover = 1.3` (`params.py:38`), `occ = 0.6022222222222221` (`params.py:39`). `1.3 × 70.0 / 0.6022222222222221 = 151.10701107011073`을 반올림해 **151**이다. 모든 품목이 같다.
- 공급자별 분할: 품목 i의 공급자 n_alt명에게 `1 + Multinomial(tot − n_alt, Dirichlet(1, …, 1))`로 나눈다 (81). 자리 순서대로 주고, 합은 `tot`다.

[기록] `occ`는 기준 몫 (0.3, 0.3)으로 운영한 튜닝 seed 10반복의 공급자 자리 점유율을 한 번 잰 값이다 (`roadmap.md:317-319`, `bench/tune.py:36-38`). 기존 가격 생성 방식에서 쟀고, 용량이 151로 바뀌기 전에 쟀다 (`roadmap.md:46`).
[확인 불가] 측정 당시 Cfg(기울기, 당시 용량)는 저장소에 남아 있지 않다. roadmap 315줄은 "직전 기울기로 한 번 재서"라고만 적었다.

[사실] k = 1 주문 한 건의 평균 수량은 (12 + 30)/2 = 21이고, 용량 151의 1/4 이하다 (`tests/test_arrivals.py::test_order_small_vs_capacity`).

### 2.8 주문 수량 범위와 k별 조정

[사실] `qty_range`: `s = qty_unit × k_ref / k`, 범위 = `(round(qty_lo × s), round(qty_hi × s))` (`src/utils/instance.py:34-36`). `qty_lo = 2`, `qty_hi = 5`, `qty_unit = 3`, `k_ref = 2` (`params.py:26-29`).

### 2.9 배송비와 기회손실

[사실] 배송비: 성립한 주문마다 `f_ship = 25.0`을 한 번 부과한다. 기간 배송비 = `f_ship × (성립 주문 수)`다 (`src/env/platform.py:46`, `params.py:92`). 개당 비용과 분할 공급 추가 비용은 없다.

[사실] 기회손실 (`platform.py:48-50`):
- 품목별 최저 공급가격: `cmin_i = min_j c_ji`. 공급가능량 > 0인 공급자만 보고, 없으면 ∞다.
- 주문 b의 잠재 거래잉여: `Σ_i q_bi (p_bi − cmin_i) − f_ship`.
- 기간 기회손실 = 성립하지 못한 주문들의 `max(잠재 거래잉여, 0)` 합이다.
- 용량 제약은 무시한다. 이윤이나 MILP에는 들어가지 않고 지표로만 쓴다.

[기록] 기회손실을 이윤에서 빼지 않는 이유: 거절의 미래 손실은 유지 가치로 반영하므로 이중 계산을 막기 위해서다 (`roadmap.md:110-111, 171-172`).

### 2.10 한 기간의 처리 순서 (코드 순서)

[사실] `src/match/interface.py:17-21`과 `src/env/platform.py:106-122`, `79-93`:
1. 정책이 현재 관측 `o`로 결정 (배정 x, 주문자 잉여 sb, 공급자 잉여 ss)을 낸다 (`interface.py:18`, `Policy.act`).
2. 정산: 결정을 검사하고 이윤 구성요소를 계산한다 (`platform.py:108`, `settle` 37-50).
3. 재참여 확률: 모든 주문자·공급자의 잉여율로 확률을 계산한다. 거절된 주문자와 미거래 공급자는 잉여 0이다 (109-110). 이 확률을 "직전 재참여확률"로 저장한다 (111).
4. 기간을 t+1로 올린다 (112).
5. 재참여 판정: 주문자는 `ret_u(주문자, 번호, t) < p`이면 남는다 (113). 공급자도 같은 방식이고, 떠나면 자리가 빈다 (114).
6. 충원: 빈 자리마다 확률 0.25로 새 공급자가 들어온다. 새 번호는 `(t+1)·n_sup + j`다 (115-116).
7. 공급 제안: 새 공급자는 프로필 그대로, 남은 공급자는 프로필에 변동을 더한다 (117).
8. 남은 주문자의 주문: 프로필에 변동을 더한다 (118).
9. 신규 주문자 도착: 포아송 수의 새 주문자가 오고, 새 관측을 만든다 (119, `_arrive` 79-84, `_observe` 87-93). 관측의 주문자 행 순서는 남은 주문자 다음에 신규 주문자이고, 공급자 행 순서는 자리 순서다.
10. 지표 기록: 참여자 수, 남은 수 (120-121).

## 4. MILP (기간별 최적화)

근거는 모두 `src/match/milp_build.py`이고, 괄호는 줄 번호다.

### 4.1 기호
- b: 이번 기간 활동 주문자, j: 활동 공급자, i: 품목.
- q_bi 요구수량, p_bi 제안가격, cap_ji 공급가능량, c_ji 공급가격. 모두 관측 `o`에서 온다.
- f = `f_ship` = 25.0.

### 4.2 결정변수 [사실]
| 변수 | 정의역 | 상하한 | 줄 |
|---|---|---|---|
| x_bji | 정수 | 0 ≤ x_bji ≤ min(q_bi, cap_ji) | 23 |
| y_b | {0, 1} | — | 24 |
| u_b (주문자 잉여) | 연속 | u_b ≥ 0 (gurobipy 기본 하한 0), 상한 없음 | 25 |
| v_j (공급자 잉여) | 연속 | v_j ≥ 0, 상한 없음 | 25 |
| P_b, P_j (구간선형 재참여확률) | 연속 | ≥ 0. 유지 가치가 주어질 때만 만든다 | 41 |

- x의 상한이 min(q, cap)이다. 그래서 주문자가 주문하지 않은 품목이나 공급자가 공급하지 않는 품목의 x는 0이다.

### 4.3 마진 [사실] (26-27)
- g_b = Σ_j Σ_i (p_bi − c_ji) x_bji: 주문 b의 거래 마진.
- m_j = Σ_b Σ_i (p_bi − c_ji) x_bji: 공급자 j가 관여한 거래 마진.

### 4.4 제약식 [사실]
1. Σ_j x_bji = q_bi · y_b, 모든 b, i (28). 묶음 성립과 분할 공급을 함께 표현한다.
2. Σ_b x_bji ≤ cap_ji, 모든 j, i (29). 공급자 용량 제약이다.
3. 규칙 기반(split = (α, β))일 때: u_b = α g_b, v_j = β m_j (30-32).
4. 그 외 정책: u_b ≤ g_b, v_j ≤ m_j (33-35).
5. Σ_b g_b − f Σ_b y_b − Σ_b u_b − Σ_j v_j ≥ 0 (36-37). 기간 합 기준의 플랫폼 이윤 제약이다.
6. 유지 가치가 주어지면 참여자마다 P_n = PWL_n(잉여_n)을 둔다 (`addGenConstrPWL`, 39-43).
   - 꺾인 점 x좌표 = w_n × r_k, y좌표 = p_k (4.6절).
   - 주문자는 u_b, 공급자는 v_j에 붙인다.

### 4.5 목적함수 [사실] (36, 38-45)
max  [Σ_b g_b − f Σ_b y_b − Σ_b u_b − Σ_j v_j] + Σ_b c_b P_b + Σ_j c_j P_j
- 대괄호 안이 플랫폼 당기 이윤이다. 유지 가치 항은 c(유지 가치)가 주어질 때만 붙는다.
- 거절된 주문자는 g_b = 0이라 u_b = 0이므로, P_b = PWL(0) = 0.5 상수가 된다.

### 4.6 구간선형 근사 [사실]
- 꺾인 점 생성 (`src/utils/pwl.py:9-12`):
  - 잉여율 r의 꺾인 점은 0부터 "재참여확률이 `pwl_hi = 0.97`이 되는 잉여율"까지 등간격 `pwl_n = 5`점이다.
  - 여기에 끝점 `pwl_rmax = 1.0`을 더해 6점, 구간 5개가 된다 (`params.py:58-60`). y좌표는 로지스틱 값이다.
- 현재 기울기의 꺾인 점 (이 문서 작성 시 계산):

| 종류 | 잉여율 r | 재참여확률 p |

| 주문자 | [0.0, 0.05249877121693709, 0.10499754243387419, 0.1574963136508113, 0.20999508486774837, 1.0] | [0.5, 0.704542712105414, 0.8504391264975321, 0.9313154660800197, 0.9699999999999999, 0.9999999352827726] |

### 4.8 정산 시 반올림과 잉여 재계산 [사실] (`src/match/milp_solve.py:26-36`)
- 최적 상태가 OPTIMAL인지 `assert`로 검사한다 (29).
- x는 `rint`로 반올림해 정수로 만든다 (31). 반올림한 x로 g_b, m_j를 다시 계산한다 (32-33).
- 잉여는 이렇게 정한다.
  - 규칙 기반: u = α g, v = β m (34-35).
  - 그 외: u = clip(솔버 u, 0, g), v = clip(솔버 v, 0, m) (36).
- 주석상 이유는 솔버 정수 허용오차(1e-5)를 정리하기 위해서다 (25).

### 4.9 환경의 검사 항목 [사실] (`src/env/platform.py:37-50`)
- x가 정수형이고 모양이 (주문자 수, 공급자 수, 품목 수)다 (39).
- x ≥ 0이고, 공급자별·품목별 Σ_b x ≤ cap다 (40).
- 성립 판정: 모든 품목에서 Σ_j x_bji = q_bi인 주문만 성립한다 (41). 마진과 잉여는 성립 주문만으로 계산한다 (42-43).
- 잉여 범위: −tol ≤ sb ≤ g + tol, −tol ≤ ss ≤ m + tol, 모양이 맞아야 한다 (44-45).
- 플랫폼 이윤: 수익 − 배송비 ≥ −tol (46-47). `tol = 1e-4` (`params.py:94`).
- 이윤 = Σ 마진(성립) − Σ sb − Σ ss − f × 성립 수 (46, 50).

### 4.10 Gurobi 설정 [사실]

### 5.4 선형 근사 [사실] (`src/vfa/linear.py`)
- 지표를 학습 데이터의 평균·표준편차로 표준화한다. 표준편차가 0이면 1로 나눈다 (20-21).
- 절편은 목표 평균이다 (22).
- 가중치는 `lstsq([Z; √λ I], [y − ȳ; 0])`로 구한다. 릿지 회귀이고, λ = 0이면 최소노름 최소제곱이다 (23-24).
- 튜닝 격자: λ ∈ (0.0, 0.1, 1.0, 10.0, 100.0), 5개다 (`params.py:75`).

### 5.5 MLP [사실] (`src/vfa/mlp.py`)
- 구조: 입력 34 → 은닉 64 (ReLU) → 은닉 64 (ReLU) → 출력 1 (26-28). `nn_hidden = 64`, `nn_layers = 2` (`params.py:77-78`).
- 파라미터 수: 6465 (이 문서 작성 시 계산).
- 입력과 목표를 학습 데이터로 표준화하고, 예측 뒤 되돌린다 (24-25, 29-30, 42). 연산은 float32다 (29-30).
- 학습 설정:
  - 옵티마이저: `torch.optim.Adam`, 학습률 `nn_lr = 1e-3` (31, `params.py:79`). weight decay는 Adam의 `weight_decay` 인자(L2)로 준다.
  - 전체 배치로 `nn_epochs = 500`회 학습하고 조기 종료는 없다 (32-35, `params.py:80`).
  - 재현성: `torch.manual_seed(nn_seed = 0)` (23, `params.py:82`), 스레드 1 (22).
- 튜닝 격자: weight decay ∈ (0.0, 1e-4, 1e-3, 1e-2, 1e-1), 5개다 (`params.py:81`).

### 5.6 설정 선택 [사실] (`src/vfa/train.py:42-47`)
- 격자의 각 설정으로 학습 분할(반복 0–23)에 맞추고 검증 분할(24–29)의 평균제곱오차를 잰다.
- 가장 작은 설정으로 전체 630개에 다시 맞춘다.
- 선형(`linear.py:33-34`)과 MLP(`mlp.py:46-47`), GNN(`gnn.py:82-83`)이 같은 함수를 쓴다. 실험 3의 MLP·MLP+편중도 요약도 이 함수에 모델 생성 함수를 넘겨 고른다 (`result/exp3_graph.py`의 `fit`, `mlp_make`).

### 5.7 유지 가치와 가드 [사실] (`src/vfa/coef.py`)
- 가드 전 값: c_n = V̂(φ(o)) − V̂(φ(o에서 n 제외)) (12-15).
  - o는 **현재 기간 관측**이다(다음 기간 상태가 아님).
  - 참여자 제외는 `features.drop`으로 그 행을 뺀 관측이다 (`src/utils/features.py:24-29`). 주문자와 공급자를 모두 계산한다 (`phi_drops`, 33-35).
- 가드 (19-22):
  1. 그 상태 안에서 같은 종류(주문자끼리, 공급자끼리)의 평균 쪽으로 줄인다: `(1 − 0.5)·c + 0.5·mean(c)` (`shrink = 0.5` = `params.py:86`).
  2. `[0, coef_hi × max(V̂(s), 0)]`로 자른다 (`coef_hi = 0.2` = `params.py:87`).
- MILP에는 가드 후 값이 들어간다 (41-42). 변환 오차는 가드 전 값으로 잰다 (`conv_err`, 36-37: 평균 절대 차이).
- [기록] "현재 관측으로 계산"하는 이유: 결정 시점에는 다음 기간 상태를 모른다 (`roadmap.md:386`). 음수 유지 가치는 0과 같은 결정을 주므로 0 하한은 결정을 바꾸지 않는다 (`roadmap.md:388`).

### 5.8 시뮬레이션 기준치 [사실] (`src/match/mc_value.py`, `src/vfa/coef.py:27-32`)
- 환경을 통째로 복사하고, 미래 난수 키만 `fkey = mc_rep0 + (rep × T + t) × mc_R + k`로 바꾼다 (`mc_value.py:12-13, 21-22`). `mc_rep0 = 1000000`, `mc_R = 10` (`params.py:72-73`).
- 복사한 환경에서 규칙 기반 정책(Cfg 몫)으로 `vf_H = 10`기간 돌린 이윤 합을 쓴다 (25-26). 원래 환경은 바꾸지 않는다.
- rollout 수: 기본 `mc_R = 10`(예측 오차), 유지 가치 변환 오차에는 `conv_R = 30`을 쓴다 (`params.py:84`, `exp1_linear_vs_nn.py:56`).
- 공통 난수: 참여자 n을 뺀 상태도 같은 미래 키를 쓴다 (`mc_value.py:23-24`; `tests/test_vfa.py::test_mc_value_drop_common_random`).
- 기준치 유지 가치: c_n^MC = mean_k(v_k) − mean_k(v_k(∖n)) (`coef.py:28-30`).
- 잡음 바닥: 같은 미래 키끼리의 차이 d_k = v_k − v_k(∖n)의 표준오차 `std(d, ddof=1)/√R`이다 (`coef.py:31`).
- [사실] 키 간격이 mc_R(10)이라 rollout을 10보다 많이 쓰면 1~2기간 뒤 상태의 키와 겹친다. 실험 1의 변환 오차 상태는 10기간 간격이라 겹치지 않는다 (`mc_value.py:11`, `roadmap.md:453-454`).

### 5.9 GNN과 MLP + 편중도 요약 [사실] (커밋 23c2d76)
- MLP + 편중도 요약 입력 (`src/env/graph.py:9-17`): 시장 요약 지표 34개 + 활동 공급자별 공급 품목 수(공급가능량 > 0)의 최댓값·분산 2개 = 36개. 모델은 MLP와 같은 구성이다 (은닉 2층 × 64, 같은 격자).
- 그래프 입력 (`graph.py:20-31`): 주문자 자리 `gnn_nb = 80`개 + 공급자 자리 `n_sup = 6`개(`params.py:84`).
  - 노드 특징은 (2 × 품목 수 + 2) = 14차원이다. 주문자 = [요구수량 6, 제안가격 6, 직전 재참여확률, 종류 0], 공급자 = [공급가능량 6, 공급가격 6, 직전 재참여확률, 종류 1]. 두 종류가 같은 열을 공유한다.
  - 활성 마스크가 있다. 연결선은 1단계로, 주문자가 원하는 품목을 공급자가 하나 이상 공급하면 1이다.
- GNN (`src/vfa/gnn.py`), torch_geometric 없음:
  - 구조: 임베딩 Linear(14, h) → 층마다 `relu(W_self h + W_msg · 이웃 평균)` × 마스크 (`gnn_layers = 2`, 26-32) → 주문자 합·공급자 합을 이어 붙여 Linear(2h, h) → ReLU → Linear(h, 1).
  - h = `gnn_hidden = 31`, 파라미터 수 6356 (`params.py:83-85`; MLP 6465의 2% 이내, `tests/test_graph.py::test_gnn_invariant_and_size`).
  - 표준화: 활성 노드 전체(두 종류 함께)로 열별 평균·표준편차를 구하고, 목표도 표준화한다 (56-64).
  - 학습량은 MLP와 같다: Adam lr 1e-3, 전체 배치 500 에폭, 조기 종료 없음, weight decay 격자 5개.
- 유지 가치 (`src/vfa/coef.py:13-22`): 모델에 입력 변환 `enc`가 있으면 [o, 주문자 하나씩 뺀 o, 공급자 하나씩 뺀 o]를 한 번에 예측해 차이를 낸다. 없으면 기존 `phi` 경로다(실험 1 재현).

- [사실] 시장 요약 지표 32–33번(평균 직전 재참여확률)은 인과 정보가 없다 [기록] (`roadmap.md:392`).
- [사실] MLP − 규칙 기반 (0.3, 0.3)의 짝지은 차이는 결정 기록과 tex에 없다. 이 문서에서 원자료로 처음 계산했다 (8절 `exp1_eval.json`).
- [사실] 연결선 밀도(k1 칸 0.34~0.35, k2 칸 0.51~0.60)는 json 밖 즉석 측정값이다 (`roadmap.md:602`).
- [확인 불가] tex가 xelatex로 컴파일되는지: 이 PC에 TeX이 설치되어 있지 않아 확인하지 못했다.
